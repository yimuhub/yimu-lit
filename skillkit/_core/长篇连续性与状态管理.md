# 长篇连续性与状态管理

> 长篇写到后期，拼的不是灵感，是「哪份记录说了算」。状态管理只有一个原则：**单一事实源，先改账本再改正文。**

## 一、权威状态库（Single Source of Truth）

每个项目只允许一份「当前状态」文件，建议命名 `state.md`，字段固定：

```
时间：第 37 天，傍晚（上一章结束于第 36 天深夜）
地点：临江码头 · 三号仓库（主角在此，搭档在二号仓库外）
人物状态：主角左臂骨裂（第 31 章受），不能提重物；搭档不知情
持有物：铜钥匙 1 把、伪造通行证 1 张、现金 320 元
已知信息：主角知道仓库主人姓周；不知道周与警局的关系
未兑现承诺：答应给码头少年找活（第 33 章）
当前目标：在换班前把箱子运出闸口
```

**规则**：正文、章卡、摘要发生冲突时，以状态库为准；要改状态，先写「变更条目 + 原因 + 生效章」，再改正文。

## 二、章卡（每章一张，写完即更新）

| 字段 | 写什么 | 不写什么 |
|---|---|---|
| 章号 / 标题 | 唯一编号 | 模糊的「上」 |
| 时间地点 | 与状态库一致 | 大约、某天 |
| 本章目标 | 谁要什么 | 主题升华 |
| 阻碍与代价 | 具体到人或物 | 「很困难」 |
| 结果 | 局面改变了什么 | 情绪总结 |
| 新信息 | 读者新知道的事 | 重复旧信息 |
| 伏笔 | 埋下/推进/兑现的 id | 「以后再说」 |
| 结尾钩子 | 下一章要回答的问题 | 纯感叹 |

章卡控制在 150 字内；超过说明本章塞了太多目标，应拆章。

## 三、伏笔账本

最少字段：`id / 埋设章 / 一句话内容 / 指向 / 到期窗口 / 状态 / 兑现章 / 兑现方式`。

- 状态只用四种：`埋下 / 推进 / 已兑现 / 废弃`。
- 「废弃」必须写原因，不能静默消失。
- 到期窗口用章号区间（如 45–55），不要写「后面」。
- 同一章最多新增 2 条伏笔；超过会让读者记忆负担过重。

## 四、卷 / 弧摘要（三级压缩）

- **卷摘要**：200–300 字，只写「目标、代价、新增变量、结尾局面」。
- **弧摘要**：80–120 字，写「这一段解决了什么、留下了什么」。
- **章摘要**：50–80 字，写「谁做了什么、结果如何、留下什么」。

写新章时注入顺序：状态库 → 当前卷摘要 → 当前弧摘要 → 最近 3 章摘要 → 相关伏笔。**不要注入全部历史。**

## 五、滚动重规划（每 10 章一次）

触发条件满足任意两条就重规划：

1. 主线目标连续 3 章没有推进；
2. 新增变量超过 3 个且没有收束；
3. 同一爽点类型连续出现 2 次；
4. 伏笔逾期数 ≥ 3；
5. 读者反馈中「拖」「乱」标签占比上升；
6. 主角当前目标与卷目标不一致。

重规划只改「未来 10 章」，不追改已发布章节；已发布部分用补丁式解释（新信息、误会、代价）修正。

## 六、写到 100 万字：什么必须记住，什么可以忘

**必须记住（永不忘）**
- 世界硬规则（力量上限、代价、禁忌）；
- 核心人物关系与不可逆伤痕；
- 主角公开承诺与未兑现债务；
- 已兑现伏笔的结论（防止重复揭晓）。

**滚动记住（近 30 章）**
- 当前位置、时间、伤势、持有物；
- 最近出现的配角与对手；
- 当前卷目标与倒计时。

**可以遗忘（需要时再查）**
- 三卷前的路人名、一次性地点描写；
- 已结束支线的细节顺序；
- 具体对话原文。

## 七、自检表

- [ ] 状态库在本章开头被读取，并在章末更新？
- [ ] 本章时间、地点、伤势、物品与状态库一致？
- [ ] 本章新增伏笔 ≤2 条，且都写了到期窗口？
- [ ] 章卡结果能一句话说清「局面变了什么」？
- [ ] 最近 10 章是否触发重规划条件？
- [ ] 有没有为了圆设定而让角色知道他不该知道的事？

## 八、反例

- ❌ 上一章左臂骨折，这一章双手搬箱，没有任何解释。
- ❌ 伏笔账本写「以后回收」，写到完结也没出现。
- ❌ 每章都把全书大纲塞进上下文，真正需要的最新状态反而被淹没。
- ✅ 先改状态库「左臂愈合：第 52 章，由医师处理」，再写搬箱；读者能看到愈合过程。
