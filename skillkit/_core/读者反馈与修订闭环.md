# 读者反馈与修订闭环

> 反馈不是命令，是线索。修订的目标是「让作品更接近它自己」，不是「让所有人都满意」。

## 一、先分类，再动手

| 反馈类型 | 例子 | 处理方式 |
|---|---|---|
| **硬错误** | 时间对不上、人物叫错、格式缺失 | 立即修，不需要讨论 |
| **理解障碍** | 「这里没看懂谁在说话」 | 补锚点、补动作，不补解释 |
| **体验问题** | 「这段想跳过」「这里很爽」 | 定位到具体段落，做增删 |
| **偏好差异** | 「我不喜欢第一人称」 | 记录，不修改，除非影响目标读者 |
| **市场判断** | 「现在流行更快节奏」 | 与作者意图对齐后再决定 |

**先修硬错误，再修理解障碍，最后才谈审美。** 顺序反了会白改。

## 二、把评分变成可执行修订项

一条可执行修订项必须包含四件事：

```
位置：第 12 章第 3 段
现象：读者不知道主角为什么突然相信陌生人
原因：缺少一个可被看见的判断依据
动作：加一句主角注意到对方鞋底沾着仓库才有的红土
```

只有「这里不好」「节奏慢」的反馈，先追问或自己定位，不要直接重写整章。

## 三、不要盲目迎合

出现以下情况时，记录但不改：

1. **样本太小**：少于 3 条同类反馈，先观察。
2. **与作者意图冲突**：目标读者不是反馈者。
3. **互相矛盾**：一半说太慢、一半说太快 → 问题在「节奏不均」而不是「整体快慢」。
4. **要求删掉核心冲突**：会让作品失去引擎，改用降低不适感的方式处理。
5. **只给结论不给位置**：无法验证，不进入修订队列。

## 四、修订批次（一次只改一类）

| 批次 | 只改什么 | 不改什么 |
|---|---|---|
| B1 连续性 | 时间、地点、伤势、物品 | 句子 |
| B2 结构 | 段落顺序、删并章、补转折 | 用词 |
| B3 场景 | 目标/阻碍/结果、动作行 | 主线 |
| B4 语言 | 重复、AI 腔、句长 | 情节 |
| B5 格式 | 场景头、标点、排版 | 内容 |

每批改完做一次回归检查：抽读首章、转折章、末章，确认没有把已修好的问题改回来。

## 五、修订记录模板

```
批次：B3
触发反馈：fb_xxx（2 条，标签「看不懂」）
改动范围：第 12 章场景 2、第 13 章场景 1
改动摘要：补主角判断依据；删一段解释性对白
风险：可能削弱悬念 → 用「红土」细节替代明说
回归：首章/第 12 章/末章抽读通过
```

## 六、自检表

- [ ] 每条反馈都已分类，硬错误已清零？
- [ ] 修订项都有位置、现象、原因、动作？
- [ ] 本次只改一类问题？
- [ ] 是否为了迎合反馈删掉了作品的核心冲突？
- [ ] 改完是否抽读关键章，确认没有引入新矛盾？
- [ ] 修订记录能让下一个人看懂「为什么改」？

## 七、反例

- ❌ 看到一条「节奏慢」就把全书砍掉三分之一。
- ❌ 读者说「不喜欢这个角色」就让他提前退场，导致主线断裂。
- ❌ 把「没看懂」当成「写得太深」，拒绝补锚点。
- ✅ 三条以上反馈指向同一段落，定位到具体句，做最小改动并回归。
