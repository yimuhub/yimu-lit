# 散文总纲 · 四操作 · 去 AI 腔

> 散文的敌人不是写不好，是**写得跟谁都能写**。

---

## 一、四个操作

同一个 skill，四种模式。**先确定模式，再动手。**

| 操作 | 做什么 | 不做什么 |
|---|---|---|
| **write（写）** | 从 brief 起草 | 不改用户已有的稿子 |
| **review（审）** | 只出诊断，不动一个字 | 不改稿 |
| **refactor（改）** | 就地最小修改 | 不重写整篇 |
| **recreate（重写）** | 整篇重写 | 不保留原句 |

**选错模式是最贵的错误。** 用户说「帮我看看哪里不对」就是 review，不是 refactor。

### 三种模式的判断依据

| 用户说 | 模式 |
|---|---|
| 「写一篇」「帮我起草」 | write |
| 「有什么问题」「帮我看看」「审一下」 | review |
| 「改一下」「改得更好」「润色」「这段太平了」 | refactor |
| 「重写」「换一种写法」「彻底改」 | recreate |

**拿不准时的默认**：先出 review 报告，末尾问一句「要我按这些改吗」。**不要擅自动手。**

## 二、写作的起点：Brief

**没有 brief 的散文写作等于抽奖。**

### Brief 必填七项

| 项 | 说明 | 缺了会怎样 |
|---|---|---|
| **体裁** | 随笔 / 抒情 / 议论 / 叙事散文 / 书评 / 人物特写 | 写成四不像 |
| **受众** | 谁看？懂多少？ | 深度错配 |
| **目的** | 读完要他做什么 / 记住什么 | 无结尾感 |
| **关系** | 你和他什么关系（陌生 / 朋友 / 权威） | 语气错 |
| **语气** | 克制 / 锐利 / 温和 / 冷 | 语域混乱 |
| **约束** | 长度、必须包含的、不能碰的 | 超长 / 漏点 |
| **事实** | 数字、事件、引文 | 空洞 |

### 事实与缺口的处理

**没有事实就别装。** 用 `[待补：具体例子]` 这样的缺口标记，不要用模糊表述填坑。

| ❌ 空洞 | ✅ 有缺口标记 |
|---|---|
| 「这带来了显著的效率提升」 | 「[待补：具体数据，如处理时长从 X 降到 Y]」 |
| 「许多研究表明…」 | 「[待补：具体研究与样本]」 |

**削减套话不能补上缺失的内容。** 稿子空洞是因为 brief 里没有实质，不是句子不够漂亮。

## 三、Voice（文风）

### 先采样，再动笔

如果用户给了文风样本，**先采样建指纹，再动笔**：

| 维度 | 采样什么 |
|---|---|
| 句长分布 | 平均句长、长短句比例 |
| 开头方式 | 常用哪种起手（场景 / 提问 / 断言 / 引语） |
| 人称与时态 | 第一人称 / 第三人称；现在 / 过去 |
| 标点习惯 | 分号频率、括号、引号、破折号 |
| 虚词 | 「其实」「当然」「所以」用得多不多 |
| 口头特征 | 高频词、口头禅、惯用句式 |
| 节奏 | 长短句交替模式、段落长度 |

**记录成文风卡，之后每次改稿都重算一次。** 如果改完指纹漂了，说明改过头了。

### 语气旋钮

写作前先设定这几个旋钮的档位：

| 旋钮 | 档位 |
|---|---|
| **直接度** | 委婉 ←→ 直白 |
| **温度** | 冷淡 ←→ 热情 |
| **个性** | 中性 ←→ 强烈 |
| **密度** | 疏 ←→ 紧 |
| **证据** | 少 ←→ 多 |
| **打磨度** | 粗 ←→ 精 |

**「读起来像这样」= 一行**：读作 [体裁] 给 [受众]，语气 [档位]，为的是 [目的]。
（这行只在用户要计划时输出。）

## 四、去 AI 腔：三层诊断

**AI 味不是词汇问题，是结构问题。** 换词治不了。

### 第一层：表达层

| 症状 | 例子 | 修法 |
|---|---|---|
| **电报体** | 短碎句连发，每句都短 | 合并成完整句 |
| **机械重复** | 三个并列句式完全同构 | 变换其中一句 |
| **空洞形容** | 「显著」「深刻」「生动」 | 换成具体感受或数字 |
| **总结句** | 结尾加一句「总而言之」 | 删掉，让最后一个细节收尾 |
| **对仗成瘾** | 每段都三句排比 | 只在真正需要处用排比 |

### 第二层：用笔层（叙事焦点）

| 症状 | 修法 |
|---|---|
| 详略失当 | 重点处反而一句带过，闲处大段铺陈 |
| 过程缺失 | 直接跳到结果，中间的手感没了 |
| 细节无功能 | 细节是装饰，不是证据或性格 |
| 场景无作用 | 场景不推进、不揭示、不调节 |

### 第三层：故事层

| 症状 | 修法 |
|---|---|
| 因果缺失 | 事件之间没有必然联系 |
| 立场漂移 | 前后态度不一致且无解释 |
| 知情顺序错 | 叙述者知道读者还不知道的事，或反之 |
| 动机缺失 | 人物行为没有可见的理由 |
| 变化无代价 | 什么都没变，也没付出什么 |

**三层都要过。** 只查词句的「去 AI 味」是治标。

## 五、五种 AI 腔套话（高频黑名单）

> 这不是全部，是出现频率最高、最该先改的。完整词表见 `skillkit/_core/`。

| 类别 | 常见表达 |
|---|---|
| **意义膨胀** | 「至关重要」「不可或缺」「具有里程碑意义」 |
| **模糊主体** | 「研究表明」「 experts 认为」「普遍认为」 |
| **空洞过渡** | 「不仅仅是……更是……」「让我们一起」 |
| **机械排比** | 「不仅……而且……同时……」三连 |
| **元话语** | 「本文将」「接下来我们来探讨」「希望本文能帮到」 |

**处理原则**：
- 意义膨胀 → 换成具体后果或数字
- 模糊主体 → 换成具体的人或来源
- 空洞过渡 → 删掉
- 机械排比 → 拆开或只留一个
- 元话语 → 全删

## 六、结构

### 散文的四种基本结构

| 结构 | 适用 | 骨架 |
|---|---|---|
| **时间顺叙** | 叙事散文、回忆 | 事情发生的顺序 |
| **主题辐射** | 随笔、议论 | 一个中心 + 若干切面 |
| **双线交织** | 复杂随笔 | 两条线在某点交汇 |
| **问题驱动** | 议论、评论 | 提问 → 展开 → 回答（并保留余味） |

### 段落层面的要求

- **一段一件事**。一段讲三件事 = 拆成三段
- **段首句是这一段的主张**（不是话题引入）
- **段尾句要么推进，要么转折，要么落定**（不要总结）

**检验**：每段的第一句连起来读，应该是一篇文章的提纲。

## 七、事实与引用

### 引用的事实要能追溯

- 数字要有出处
- 引语要**逐字准确**，不能改写后加引号
- 转述要标明是转述（「据他回忆」）

### 不要用权威替代论证

「哈佛的一项研究表明……」如果说不出是哪项研究，就是**模糊权威**，读者没法核实。

**修法**：
- 知道 → 写清楚出处
- 不知道 → 换成你自己的观察，标明是观察
- 需要引用但没来源 → `[待补：出处]`

## 八、修订流程

```
1. 通读一遍，不改，记下「哪里不对」
2. 先出 review 报告（位置 / 问题 / 后果 / 最小改法）
3. 确认范围后，逐条处理
4. 改完重算文风指纹，对比漂移
5. preflight 终检
```

### review 报告格式

| 位置 | 问题 | 读起来的后果 | 最小改法 |
|---|---|---|---|
| 第 3 段第 2 句 | 「显著提升」无具体所指 | 读者会怀疑你在编 | 换成具体数字或删掉 |

**「读起来的后果」这一栏不能省。** 只说「这里不好」没有行动价值。

### refactor 的最小改动原则

**每一处改动都要能说出理由。** 「虽然这个词不是我本来会用的」不是理由。

允许的理由：
- 语法/用词错误
- 歧义
- 与事实矛盾
- 违反 brief 的约束
- 填充物（说了句子里已有的信息）

**改到第二遍时，把说不出理由的改动全部改回去。**

---

## 九、preflight 终检

交稿前逐条过：

- [ ] 体裁明确（读起来就是那一类）
- [ ] 受众匹配（深度没有超出对方）
- [ ] 目的达成（读完知道要做什么/记住什么）
- [ ] 有具体事实，缺口有标记
- [ ] 段落各讲一件事
- [ ] 无 AI 腔套话
- [ ] 无元话语
- [ ] 引用准确可追溯
- [ ] 结尾落得住（不是总结句）
- [ ] 文风指纹与样本一致
- [ ] 字数在约束内
- [ ] 念一遍不卡

---

## 十、自检

- [ ] 操作模式选对了（write / review / refactor / recreate）
- [ ] brief 七项齐了
- [ ] 有文风样本时先采样
- [ ] 语气旋钮已设定
- [ ] 三层去味都过（表达 / 用笔 / 故事）
- [ ] review 报告含「后果」与「最小改法」
- [ ] refactor 的每处改动都有理由
- [ ] preflight 12 条全过
