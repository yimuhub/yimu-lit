# 编剧室 · 提案 · 反馈 · 情景喜剧

> 编剧室不是会议室，是**共同写作的机器**。流程设计得好，烂点子也能变好；流程坏，好点子也会被写死。

---

## 一、编剧室的基本分工

| 角色 | 职责 | 不能做 |
|---|---|---|
| **主创 / showrunner** | 最终决定权，守住引擎与调性 | 什么都自己改 |
| **制片人** | 预算、排期、平台关系 | 越权改内容 |
| **编剧** | 写戏 | 私自改引擎 |
| **剧本编辑 / 统稿** | 一致性、格式、前后连贯 | 改创意 |
| **制片主任 / 场记** | 预算可行性 | — |

**铁律：只有一个最终决定权。** 所有人都能提意见，但只有一个人拍板。多人拍板 = 没人拍板 = 戏写不出来。

---

## 二、提案是面试

**主创听提案时问的不是「好不好」，是「这个人会不会写」。**

判断一个提案的四个维度：

1. **具体度**：能想象出画面，还是只有概念
2. **可执行**：在预算和时长内做得出吗
3. **独特性**：换个人写会不会一样
4. **引擎兼容性**：放进这个剧会不会稀释主线

### 提案不该被否掉的情况

提案粗糙 ≠ 不可救。**先给方向，再给细节。**
「这个想法有 60 分，但这里的第二幕塌了，我们一起修第二幕」比「不行，重写」有用得多。

### 提案模板

```
一句话：这个故事讲 ______ 想要 ______，但 ______ 挡着
主角的困境：______________________________________________
最有戏的一场：__________________________________________
这和主引擎的关系：________________________________________
我能想到的最好的版本：____________________________________
```

## 三、修改意见的纪律

### 提意见的方式

| ❌ 破坏性 | ✅ 建设性 |
|---|---|
| 「这段很烂」 | 「这场戏里主角没有目标，观众不知道他在争什么」 |
| 「你不理解这个故事」 | 「这里的转折和第三幕的兑现对不上」 |
| 「按我说的写」 | 「我担心这场戏的时长会超时，我们看看能不能砍」 |

**提意见要指向具体位置和具体后果。** 「这里不行」没有信息量。

### 反馈的三个层次

1. **必改项（must fix）**：不改不能过。列出 3-5 条，不超过 5 条
2. **建议项（should fix）**：能改更好
3. **可选项（nice to have）**：锦上添花

**每轮反馈必改项不超过 5 条。** 超过 5 条，编剧会顾此失彼。

### 「修改轮次」的边界

**不要用轮次无限消耗编剧。** 约定：
- 第 1 轮：大改（结构）
- 第 2 轮：中改（场景与场次）
- 第 3 轮：小改（润色）
- 第 4 轮：终审（找漏洞，不再重写）

每一轮之前，把**上一轮的必改项**列出来逐条打勾。**没打勾的不算完成。**

## 四、编剧室的工作节奏

| 环节 | 产出 | 谁定 |
|---|---|---|
| 分集会议 | 本集核心问题 + 场次表 | 主创 |
| 写稿 | 场次草稿 | 编剧 |
| 桌读（table read） | 口头表演的实感 | 全体 |
| 审读 | 必改项清单 | 主创 + 编辑 |
| 修订 | 修订稿 | 编剧 |
| 定稿 | 交付稿 | 主创签字 |

### 桌读的价值

**桌读能发现写不出来的问题。** 有些戏读起来就是别扭——因为它没有在人的嘴巴里活过。

桌读要记录：
- 有人念不出来的句子
- 需要解释才懂的情节
- 笑声出现的位置（太早或太晚）
- 沉默的长度（念不下去的地方）

### 修订留痕

每轮修订**不改上一轮的结构决策记录**，只追加。**能看出戏是怎么长出来的**，比「一次改对」更有价值。

## 五、情景喜剧（30 分钟）

### 前提驱动的喜剧

** sitcom 的第一性原理：一个前提 + 三级困境。**

**前提（Premise）** 一句话：谁 + 想要什么 + 但有个荒谬的障碍。

**三级困境**：
1. **外部困境**（他解决不了的事）
2. **内部困境**（他的性格让事情更糟）
3. **人际困境**（别人的反应让事情更糟）

**每集都是同一个前提在不同情境下的表现。** 不是新故事，是新借口。

### 九种困境原型

| 原型 | 表现 |
|---|---|
| 想做 A，但被迫做 B | |
| 想隐藏 X，但 X 藏不住 | |
| 计划失败，因为缺一个零件 | |
| 需要钱，但没有 | |
| 需要帮助，但求助的对象更糟 | |
| 目标是明确的，路径全错 | |
| 情况好转，然后变坏 | |
| 知道该怎么做，但身体不配合 | |
| 大家都想帮忙，结果全搞砸 | |

### 笑点力学

**包袱的三个部分：**
1. **设置**（setup）：建立预期
2. **预期**（expectation）：观众以为会这样
3. **落差**（turn）：结果是那样

**笑点强度 = 落差的大小 × 建立的投入度。**

建立得越久，落差越大。**急转弯不好笑，被绕进去才好笑。**

### Topper（尾梗）

一场戏的最后一个笑点，**冲淡了前面的紧张**。

- 前面越严肃，topper 越好笑
- topper 要短
- topper 不能是本集主笑点（主笑点通常在更前面）

### 场景数与结构

30 分钟情景喜剧：

| 块 | 页数 |
|---|---|
| 冷开场 | 1-2 |
| Act A | 到 6 页 |
| Act B | 到 21 页 |
| Act C | 到 26 页 |
| Act Out | 到 28 |

**场景数控制在 6-8 个**（含 A/B 故事）。

### 规则

- **多机位 sitcom**（《老友记》式）：4-6 个固定机位，场景少，重复率高
- **单镜头 sitcom**（《破产姐妹》式）：镜头自由，可以走出演播室
- 两种的写作方式不同，**不可混用格式**

### sitcom 特有的写作禁忌

- ❌ 角色说出自己的聪明（观众要自己发现）
- ❌ 解释笑点（「这就是我说的那个意思」）
- ❌ 连续三个同类型的笑点（节奏单一）
- ❌ 让角色做不符合其性格的事（除非是明确的成长点）

## 六、自检表

- [ ] 只有一个最终决定权，且明确到人
- [ ] 提案按「具体度/可执行/独特性/引擎兼容」四维评估
- [ ] 每轮反馈必改项 ≤ 5 条，且指向具体位置与后果
- [ ] 修订轮次有明确边界（3 轮 + 终审）
- [ ] 桌读记录已归档
- [ ] 情景喜剧：前提一句话 + 三级困境齐备
- [ ] 每个笑点有完整的 设置/预期/落差 三段
- [ ] topper 与主笑点分开
- [ ] 场景数在预算内
