# 剧集引擎 · 人物网 · 季弧 · 剧集圣经

> 剧集不是一部长电影，是**一台能持续产出冲突的机器**。引擎坏 = 剧集死。

---

## 一、剧集引擎

**引擎 = 一个能自动生产冲突的结构。** 检验标准：写完第 1 季后，第 5 季还能不能自动有戏。

### 引擎的三个部件

1. **稳定的核心矛盾**（不随季变化的根本对立）
2. **持续自我复位的状态**（每集结束都回到原点，但代价在累积）
3. **能不断引入新元素的接口**（新人物、新规则、新后果）

### 五大常见引擎

| 引擎 | 结构 | 例 |
|---|---|---|
| **任务驱动** | 一集一个任务，任务失败就升级 | 刑警办案 |
| **身份错位** | 主角必须持续扮演一个不是自己的人 | 卧底 |
| **关系债务** | 每集还一笔债，还完得到新的债 | 家族债务 |
| **规则系统** | 固定规则 + 不断测试边界的个案 | 律政所按流程办案 |
| **资源流失** | 每集消耗一个不可再生的资源 | 时间/寿命/经费 |

**一个剧集最好只有一个主引擎 + 一个副引擎。** 两个以上会互相稀释。

### 引擎压力测试

问四个问题：
1. 第 1 季用掉了引擎的多少？还剩多少？
2. 主角可以赢几次？赢到第几次就不能再赢了？
3. 观众第 10 集还会问「这一集会怎样」吗？
4. 有没有**每次都变一点**的机制（避免重复）？

## 二、人物网

### 三种关系结构

| 结构 | 说明 | 适合 |
|---|---|---|
| **中心辐射** | 一个核心人物，多个关系各异的配角 | 主角戏（容易疲劳） |
| **三角** | 三个人两两有张力 | 稳定且可持续 |
| **网状** | 所有人互有关联 | 群像（最难，最有后劲） |

**推荐**：网状 + 一个轴心人物（知道全貌的那个）。

### 群像的三个设计工具

1. **共享秘密**：所有人被一件事绑定，轴心人物知道全貌
2. **信息差**：观众知道 A，主角知道 B，配角知道 C
3. **未结清单**：每两人之间有一件没解决的事，每集解决一件，同时制造两件新的

### 角色功能分工

一季戏里，每个主要角色必须至少承担一项**结构性功能**：

| 功能 | 作用 |
|---|---|
| **推进者** | 主动推动主角行动 |
| **阻碍者** | 给主角制造麻烦 |
| **镜子** | 让主角照见自己 |
| **催化剂** | 触发重大转折 |
| **黏合剂** | 连接其他角色，调节张力 |
| **观众代言人** | 说出台下观众想说的问题 |

**每季至少有一个角色的功能要变化**（比如阻碍者变成催化剂），否则角色会僵死。

## 三、季弧

### 一季的基本结构（美式）

| 集数 | 功能 |
|---|---|
| 1-3 | 建立世界与关系（**Pilot 必须自足**） |
| 4-8 | 试探边界，展示引擎 |
| 9-12 | 第一次重大危机 |
| 13-20 | 复杂化，人物关系变形 |
| 21- | 收束，但留下更大的问题 |

### 季的核心问题

**每季只问一个核心问题。** 这一季所有的情节都在回答它。

写法：`这一季结束时，[主角] 必须承认 ____。`

好例：「这一季结束时，他必须承认自己变成了他父亲。」

### 季的三种结局类型

1. **关门**：主要问题解决，但代价巨大（**最好用**）
2. **开门**：解决了小问题，开了大问题（用于续订）
3. **悬置**：什么都没解决，只加深了（慎用，容易被骂）

### 季中点（Mid-season）

- 约第 10 集（22 集剧）
- 打破第一季建立的平衡
- 常见手法：背叛、真相揭露、身份暴露、阵营倒转

### 季终集

**季终集不是「更好的第一集」。** 它必须：
- 结算本季的核心问题
- 兑现本季埋的伏笔
- 制造下一季的引擎
- 给一个**不可逆的**结尾

### 集尾钩子（ Cliffhanger）的分级

| 级别 | 手法 | 效果 |
|---|---|---|
| **A** | 揭示（reveal）——揭开一个身份/事实 | 中 |
| **B** | 倒计时——炸弹/绝症/最后期限 | 强 |
| **C** | 反转——刚建立的认知被推翻 | 强 |
| **D** | 情感爆破——关系彻底断裂 | 很强（用多了会腻） |
| **E** | 不可逆行动——主角做了不能撤回的事 | 最强 |

**不要每集都用 D/E。** 全季都用最高级，观众会麻木。轮换使用。

## 四、剧集圣经（Series Bible）

### 必备章节

```
1. 剧名 / 类型 / 时长 / 集数 / 目标受众 / 平台
2. logline（一句）
3. 类型契约：观众会看到什么 / 为什么还在看 / 得到什么
4. 主题与控制思想
5. 剧集引擎（主引擎 + 副引擎 + 自我复位方式）
6. 主要人物（每人一页：功能 / 背景 / 声音 / 弧光 / 关系）
7. 人物关系图（谁和谁有未结的事）
8. 世界设定（只写影响剧情的）
9. 季弧：本季核心问题 + 幕点分布
10. 分集梗概（每集一句）
11. 术语表 / 专有名词
12. 视觉基调（色调、镜头倾向、场景质感）
13. 禁区（不能做的事：尺度、角色死亡方式、类型纯度）
```

### 圣经的作用

1. **给制片方看**：证明这个剧能跑 5 季
2. **给编剧室用**：统一设定，避免矛盾
3. **给新人用**：上手说明书
4. **给市场用**：一句话说清卖点

**圣经的核心是「引擎」那一章。** 其它章节都可以改，引擎不行。

## 五、试播集（Pilot）

### 试播集必须做到

1. **自足**：没看过前集的观众完全看得懂
2. **展示引擎**：让观众知道这剧是怎么运转的
3. **建立最关键的关系**：至少两对
4. **给一个完整的情绪弧**：不是只有悬念，要有一个小满足
5. **留下一个必须追下去的问题**

### 试播集不能做

- 花三分钟交代世界背景
- 介绍所有主要角色（一次最多两三个）
- 靠一个惊吓钩子撑（这是短剧的做法，长剧集会被认为不专业）
- 埋太多未解之谜

### 试播集的最后一场戏

**要有一个「为什么现在要追这剧」的瞬间。** 通常是：
- 主角做出了有代价的选择
- 真相被揭开一角
- 关系被彻底改变

## 六、分集大纲模板

```
第 7 集《标题》
时长：45 分钟 | 场景数：8 | 主要地点：3
本集核心问题：______
本集类型节拍命中：2 / 4 / 8
场次表：
  1  内景  警局会议室  日   —— 布置调查方向
  2  外景  停车场  晨      —— 遇到旧线索
  3  内景  嫌犯家  日     —— 审讯，反转
  ...
集尾钩子：B 级（倒计时）
本集结束时的状态与开篇时相比：______
```

## 七、剧集自检表

- [ ] 引擎清晰，写下了「观众为什么还在看」
- [ ] 引擎压力测试：赢几次会失效
- [ ] 每季一个核心问题
- [ ] 群像有共享秘密 + 信息差 + 未结清单
- [ ] 每个角色有结构性功能，且本季有功能变化
- [ ] 季中点有明确的平衡打破
- [ ] 季终集结算 + 兑现 + 开新引擎
- [ ] 集尾钩子分级轮换，不是都用最高级
- [ ] 试播集自足、展示引擎、留下追看理由
- [ ] 剧集圣经十三章齐全，引擎章最扎实
- [ ] 每集有：核心问题 + 场次表 + 钩子等级 + 状态对比
