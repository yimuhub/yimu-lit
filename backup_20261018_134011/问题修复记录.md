# 问题修复记录 · novel-bot

## 2026-10-17 多模型供应商层（新增功能 + 缺陷修复）

### 需求
- 增加「模型供应商」管理：可**自定义**绑定 + 预设**一键绑定**，可**同时绑定多个**。
- 创作时可从已绑定供应商里**选择不同的大模型**进行创作。
- 原有默认供应商（Agnes）必须迁移进来继续可用，行为不破坏。

### 改动文件
| 文件 | 改动 |
|---|---|
| `bot/providers.py` | 新增。供应商数据层：`providers.json` 存储/迁移、预设表、CRUD、`resolve(cfg)`、`/models` 拉取、探活 |
| `bot/llm.py` | `chat/chat_json` 增 `cfg` 参数，按 `resolve(cfg)` 选供应商/模型；加 `[llm]` 命中日志 |
| `bot/workflow.py` | 所有 llm 调用透传 `cfg`（提取/补全/人物/大纲/文风/书名/写章/扩充/元数据/校准） |
| `bot/writer.py` | 第1章文风校准 `style_calibrate` 传入 `cfg` |
| `app.py` | 供应商 CRUD/测试/拉模型/默认/启停 路由；`/api/chat` 收 `provider_id`+`model` 并写入 session.cfg |
| `static/index.html` | 「模型供应商」侧栏面板（列表/启停/设默认/测试/拉模型/删除）+ 绑定模态（预设/自定义）+ 输入框上方「供应商+模型」选择器 |
| `providers.json` | 新增（首次从 `config.json.llm` 迁移 Agnes 为默认 active，`config.json` 保留不动） |

### 关键设计（并发安全）
- 供应商/模型选择「随任务走」：写进 `cfg['_provider_id']/_model`，每个后台写作线程只认自己 cfg 里的选择。
- **禁用模块级「当前供应商」全局态**——多项目并写会被后写覆盖、串台。
- `resolve(cfg)` 三级安全回落：cfg 指定 → `default_provider` → 第一条 active → 全没有才抛「请绑定一个模型供应商」。

### 发现的缺陷（已修复）
1. **死锁**：`providers.py` 用非可重入 `threading.Lock`；CRUD 函数持锁后调 `load_data()`（也取锁）→ 同一线程自锁，服务卡死。
   - 复现：`POST /api/providers` 挂起 180s 无返回。
   - 修复：改 `threading.RLock()`。验证：40 线程 × 20 次 add+resolve+remove，0 死锁 0 异常。
2. **未定义变量**：`add_provider`/`update_provider` 里误写 `_VALID_MODEL`（常量名是 `VALID_MODEL`）→ `NameError`。已改。
3. **预设绑定撞 id 直接报错**：重复一键绑定同预设时 id 冲突会 `id 已被占用`。改为预设默认 id 走 `_next_id` 自动加后缀（`openai`→`openai-2`），显式指定 id 撞车仍报错。

### 安全 / 校验
- `base_url` 必须 http/https（本地 Ollama 允许 `http://127.0.0.1`），`ftp://` 等一律拒。
- 模型名走白名单正则；`id` 走 slug 校验。
- API key 只存本地（inline 或 `api_key_file`），列表接口一律**打码**（`已设置（sk-…Km）`），不外发、不进日志。
- 删除保护：唯一 active 供应商不可删；删默认供应商自动切到剩余 active。

### 验证记录（真实 HTTP）
- `GET /api/providers` / `POST` / `PUT` / `DELETE` / `default` / `active` / `test` / `models`：全部 200/预期。
- 预设一键绑定、自定义绑定、自动加后缀：通过。
- 拉 `agnes` 的 `/models`：`from_api=True`，拿到 10 个真实模型。
- **路由决定性验证**：加一个指向 `127.0.0.1:59999`（不可达）的 probe 供应商，创作请求指定 `provider_id=probe` → 报 `[Errno 61] Connection refused`（证明确实路由到 probe）；不带 provider 走默认 Agnes → 成功进入 options。证明 payload 的 `provider_id`/`model` 真的驱动了 LLM 调用。

改动前已备份到 `backup_20261017_231057/`（app.py、bot/llm.py、bot/workflow.py、static/index.html、config.json）。

## 2026-10-18 续写 + 预览 + 供应商面板升级

### 需求
1. **续写**：已完成的作品可「点开后继续写」——在现有章节后追加 N 章，承接前文。
2. **预览**：已写好的内容可点击直接预览（成书全文 / 逐章切换）。
3. **供应商面板升级**：
   - 拉取模型后，模型可**点击设为该供应商的默认模型**。
   - 多个供应商时**自动重叠收起**（组级折叠），点一下展开再逐个操作；默认供应商卡片也收起，非默认展开。

### 改动文件
| 文件 | 改动 |
|---|---|
| `bot/writer.py` | 新增 `append_chapters(proj, extra)`：给计划追加 `extra` 章，标 `continuation=True`、状态回 `in_progress`；`_build_ctx` 传 `continuation` 标记 |
| `bot/workflow.py` | `write_chapter` 检测 `ctx['continuation']` → 用「承接前文、不复述既成事件、从上一钩子续」的专属提示词 |
| `app.py` | `/api/continue` 增 `extra` 参数（对已完成/未完成作品都能加章，复用作品默认供应商/模型）；新增 `GET /api/preview`（成书全文或已写章节拼接 + 章节清单 + 字数） |
| `static/index.html` | 作品卡片加「👁 预览 / ▶ 续写 / ⬇ 成书」按钮；预览模态（`#pvmodal`，全文/逐章下拉 + 轻量 md 渲染）；供应商面板加组级折叠条 `#provsum`（多供应商自动收起）+ 卡片体可折叠（默认供应商收起）+ 模型标签可点击设默认 |

### 关键设计
- **续写不污染原书**：追加的章节标 `continuation=True`、文件名 `第NN章-续写.md`，与正文章节区分。
- **预览走后端**：前端只渲染，正文/章节由 `/api/preview`、`/api/chapter` 提供；`mdLite` 先转义再轻量排版（标题/引用/列表/分隔线/加粗），防注入。
- **默认模型是供应商属性**：`providers.json` 每个 provider 存 `default_model`；点击模型标签 → `PUT /api/providers/{id} {default_model}` → `/api/model_options` 即时跟随。

### 验证记录（真实 HTTP + 真实 LLM 写）
- `GET /api/preview`（吐槽宫女升职记，20章）：`has_book=True`、`text_len=93196`、章节 20 → 200 ✅
- `PUT /api/providers/agnes {default_model:agnes-3.0-flash}`：`now_default=agnes-3.0-flash`，`/api/model_options` 跟随 ✅（已设回 2.5-flash）
- **续写端到端**：复制一个 3 章作品到临时 key → `POST /api/continue {extra:1}` → 计划变 4 章（第4章 `continuation=True`）→ 后台线程写出 `第04章-续写.md`（≈8169 字），开头「承接第3章陈国栋被捕后的结局…」**正确接住前文** ✅（测试后已删除临时项目，用户两本真实作品 20/20、3/3 未动）
- 前端：`node --check` 全脚本语法通过；`pselect/mselect/pvhint/provsum/provlist/pvmodal/pvtitle/pvbody/pvch/pvdow` 等 11 个 DOM id 均在位。
